How it works

Each panel below shows the exact request and the exact response. Scroll for the next step.

Step 01 · ~120 ms

Start a verification session

Create a session, pick the integration mode, and get back a hosted WebView URL or an SDK token. Sessions expire after 10 minutes and are idempotent on retry.

// POST /v1/sessions body = { "mode": "webview", "locale": "bn-BD", "expiry_secs": 600 } // → 200 OK { "ok": true, "data": { "session_id": "ses_a1b2c3" } }
2
Step 02 · ~680 ms

Collect identity data

Upload NID front and back images, capture a selfie, and run a passive liveness check — all in one multipart request. Storage is encrypted in transit and at rest.

// multipart/form-data · /v1/uploads/{session_id} formData.append("front_image", file://front.jpg) formData.append("back_image", file://back.jpg) formData.append("selfie", file://selfie.jpg) formData.append("liveness", true) // → 202 Accepted · upload_id returned
3
Step 03 · ~140 ms

Receive the verified JSON

Run the verification, then read the structured { ok, data, error } envelope. Score fields are normalized so the same shape works for every endpoint.

// POST /v1/nid/verify body = { "session_id": "ses_a1b2c3" } // → 200 OK { "verified": true, "name_en": "Md. Rafiqul Islam", "nid": "••••••••4821", "match_score": 0.994, "liveness_score": 0.97 }

The single API call

One endpoint, one envelope

Every step collapses into a single POST /v1/nid/verify call. You pass the session, the images, and the liveness flag — the platform handles the rest.

// POST /v1/nid/verify fetch("https://api.adeptsense.tech/v1/nid/verify", { method: "POST", headers: { "x-api-key": ADEPT_KEY }, body: formData // front, back, selfie, liveness }) .then(r => r.json())

Decision notes

A quick heuristic for each pattern based on your research artifacts (AdeptSense_UX_Market_Research_Report.md, competitors.md, adeptsense-ia.md). Pick the one whose trade-off matches the page beneath it.

Pattern A

Timeline

Reads as one continuous journey. Best when the reader is genuinely learning the flow. Doubles scan time vs. cards. Stripe-style.

Pattern B

Tabbed terminal

Highest developer conversion — they see the wire format before they ever talk to sales. Needs a real swap interaction (light JS).

Pattern C

Card grid v2

Same shape as today's live version, denser. Each card carries a snippet. Flow strip stitches the cards into one pipeline.

Pattern D

Sticky-scroll narrative

Slow, deliberate, editorial. Best for a scroll-driven homepage hero below. Tall — won't fit above-the-fold.

Pattern E

Bento flow

Highest information density per square inch. Reads as one piece. Asymmetry carries the eye to the live-stat tile. Most on-brand for the current visual language.

Self-contained · no JS (the B tabs are static) · tokens inherited from src/css/tokens.css · uses Plus Jakarta Sans + Lora + JetBrains Mono · safe to delete after review
