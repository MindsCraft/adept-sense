Three steps

From document to decision.

The same JSON contract every endpoint returns. Sessions are idempotent, retries are safe, and verified payloads are signed.

Step 01 · ~120 ms

Start a verification session

Create a session, pick the integration mode, and get back a hosted WebView URL or an SDK token. Sessions expire after 10 minutes and are idempotent on retry.

// POST /v1/sessions
body = {
  "mode": "webview",
  "locale": "bn-BD",
  "expiry_secs": 600
}

// → 200 OK
{ "ok": true, "data": { "session_id": "ses_a1b2c3" } }
~120 ms token generation Idempotent retries 10-min session TTL
Step 02 · ~680 ms

Collect identity data

Upload NID front and back images, capture a selfie, and run a passive liveness check — all in one multipart request. Storage is encrypted in transit and at rest.

// multipart/form-data · /v1/uploads/{session_id}
formData.append("front_image", "file://front.jpg")
formData.append("back_image", "file://back.jpg")
formData.append("selfie", "file://selfie.jpg")
formData.append("liveness", true)

// → 202 Accepted · upload_id returned
~680 ms upload Encrypted AES-256 Passive biometric check
Step 03 · ~140 ms

Receive the verified JSON

Run the verification, then read the structured { ok, data, error } envelope. Score fields are normalized so the same shape works for every endpoint.

// POST /v1/nid/verify
body = { "session_id": "ses_a1b2c3" }

// → 200 OK
{
  "verified": true,
  "name_en": "Md. Rafiqul Islam",
  "nid": "••••••••4821",
  "match_score": 0.994,
  "liveness_score": 0.970
}
~140 ms inference Normalized 0.0–1.0 scores Signed JSON envelope
